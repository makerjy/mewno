# 2026-11-18 로컬 검증

Apple M5, CPU 10코어, macOS 26.6.2 arm64. 앱에서 읽은 총 메모리는 32.0 GiB였다. 요청서에 적힌 36 GB는 실제 측정치로 사용하지 않았다.

## 실음성과 작업 상태

HappyMidnight의 공개 한국어 대화로 시험했다. MP3 원본은 약 15초다. Base가 언어를 ko로 감지했고 첫 구간은 ‘안녕하십니까 조세프 씨’, 다음 인사 중에는 ‘만나서 반갑습니다’를 인식했다. ‘찬호’를 ‘찬옷’으로 잘못 인식한 사례가 있다. 이름 표기는 녹음과 대조해야 한다. 이 한 파일로 의미 정확도나 일반 성능을 추정할 수 없다.

| 설치본 sidecar로 실행한 입력 | 언어/경로 | 결과 |
|---|---|---|
| MP3, MPEG Layer III | 자동 언어, AVFoundation, 자동 가속 | 15,030 ms, 7개 구간, ko |
| M4A, AAC | 한국어, AVFoundation, CPU | 15,018 ms, 7개 구간 |
| WAV, PCM16 | 한국어, 수동 WAV, CPU | 15,018 ms, 7개 구간 |
| MP4, H.264 영상 + AAC 오디오 | 자동 언어, AVFoundation | 15,018 ms, 7개 구간, ko |
| 1시간 무음 뒤 대화를 붙인 PCM16 WAV | 한국어, CPU | 총 3,615,018 ms. 첫 구간 시작 3,600,000 ms |
| 무음 PCM16 WAV | 한국어, CPU | 한국어 무음 오류, 결과 미생성 |

외부 IP 연결을 금지한 프로파일 아래에서 설치본 sidecar로 0.1.2 Rust 시험 다섯 그룹이 모두 통과했다. 잘린 UTF-8 토큰의 원래 바이트를 보존하는 회귀 시험을 포함한다. 데이터베이스 재개방, 편집본과 원문의 분리, 편집 Markdown 생성, 중복 제외, 원자적 배치 실패 처리, 중단된 작업 복구, 대기 및 실제 인식 중 취소, 취소 후 재시도를 포함한다. 장시간 시험은 시간 오프셋과 무음 처리를 검증한다. 1~3시간 내내 실제 대화가 이어지는 부하 시험은 남아 있다.

## 추가 디코딩과 모델 범위

같은 공개 녹음을 개발용 FFmpeg로 다른 형식으로 변환하고 앱에 포함된 디코더의 종료 상태와 PCM 크기를 확인했다.

| 결과 | 실제로 시험한 조합 |
|---|---|
| 약 15초 PCM 출력 | M4A/AAC, MP3/Layer III, WAV/PCM, AIF와 AIFF/PCM, CAF/PCM, FLAC, MP4·MOV·M4V/H.264+AAC, Ogg/Vorbis, Ogg/Opus |
| 부분 출력 | ADTS AAC는 종료 상태가 성공이었으나 12.8초만 출력됐다. 이 조합의 전체 길이는 보장할 수 없다. |
| 트랙 읽기 실패 | WebM/VP9+Opus, MKV/H.264+Opus, WMA/WMAv2 |

Whisper Base는 앱 다운로드·해시 검증 및 CPU/Metal 인식을 실행했다. Tiny와 Small은 고정 매니페스트에 등록했으며 이 기기에서 실제 추론 검증을 수행하지 않았다. Windows, Linux, Intel Mac, macOS 14 실기기는 검증하지 않았다.

## 화면 원본과 독립 검토

프로젝트의 Figma Make 파일에 대한 get_design_context(0:1)가 원본 링크를 반환했다. MCP 리소스 읽기는 Unknown resource, 별도 Figma 연결은 OAuth 재인증 오류였다. get_screenshot은 Make 형식을 지원하지 않았다. 사용자가 제공한 원본 ZIP에서 App.tsx, main.tsx, index.css, 로고, 고양이, 폰트를 가져왔고 브라우저의 Make 실제 미리보기와 패키지 창을 시각적으로 비교했다. 고양이 PNG는 184×134, 워드마크는 268×90이며 원본 종횡비와 다크 변형을 유지했다.

초기 설정의 용도 선택, 추천 기준, 선택 입력은 사용자의 UI 수정 요청으로 재설계했다. 한 가지 기준을 고르는 컨트롤에는 [Apple의 segmented controls 지침](https://developer.apple.com/design/human-interface-guidelines/segmented-controls)을 참고했다. 용어 입력에는 [Otter의 인명·전문 용어 안내](https://help.otter.ai/hc/en-us/articles/26660468516631-Transcribe-conversations-in-different-languages-with-Otter)를 참고했다.

별도 코드 검토에서 결과 창 닫기 권한, 종료 시 다운로드 자식 프로세스 정리, 같은 경로의 원본 교체 감지, 손상 모델 재설치 안내를 지적했다. 네 항목을 수정했다. 이 검토는 같은 모델 계열의 별도 에이전트가 수행했다.

## 0.1.2 결과 화면과 한영 혼합 녹음

설치 이미지를 검증하고 응용 프로그램 폴더에 설치했다. 설치본의 모델별 설명, 화면 테마, 파일 읽기 방식, CPU 전용 스위치를 확인했다. 공개 한국어 녹음에서 타임스탬프를 누르자 재생기가 8초로 이동했다. 편집본 복사 성공 안내를 확인했고 macOS 저장 창에서 내보낸 UTF-8 Markdown에 수정된 문장과 타임스탬프가 함께 들어 있었다.

화면 동작 시험에서는 배포용 프런트엔드에 시험용 600개 구간과 공개 오디오를 연결했다. 1160×810, 720×540 두 창에서 재생 중 표시 구간이 바뀌어도 재생바의 세로 위치가 유지됐다. 수동 스크롤과 편집 시 따라가기 해제, 다시 켰을 때 현재 구간 복귀, 원문 전환을 확인했다. 이 시험의 구간은 긴 목록의 동작을 확인하기 위한 데이터다.

공개 한국어 대화 약 15초와 whisper.cpp의 영어 JFK 샘플 약 11초를 이어 붙여 Base CPU로 전사했다. 자동 감지는 ko를 반환했고 한국어 대화는 한글, 영어 연설은 영어로 출력했다. 한국어를 직접 지정한 실행에서도 같은 결과가 나왔다. 한 문장 안에서 언어가 자주 바뀌는 경우와 전문 용어의 철자 정확도는 이 시험으로 평가하지 않았다.
