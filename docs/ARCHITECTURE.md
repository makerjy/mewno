# 로컬 전사 구조

React는 Tauri 명령으로 현재 작업 상태와 편집 결과를 읽습니다. 파일 선택은 macOS 선택 창, 드래그는 Tauri의 파일 드롭 이벤트를 사용합니다. 디렉터리와 존재하지 않는 경로는 큐에 넣지 않습니다. 여러 파일 추가는 한 트랜잭션이며 실행 중인 동일 경로는 중복 제외합니다.

Rust 작업자 한 개가 SQLite의 삽입 순서대로 작업합니다. 대기 → 모델 확인 → 음원 변환 → 구간 준비 → 전사 → 완료로 진행합니다. 앱이 다시 열리면 대기 작업을 이어가며, 실행 중 중단된 작업에는 재시도를 표시합니다. 취소된 작업의 일부 전사문은 게시하지 않습니다.

AVFoundation sidecar는 첫 오디오 트랙을 16 kHz 모노 PCM으로 스트리밍합니다. 수동 WAV 경로는 PCM16 모노 16 kHz 헤더를 검사합니다. 현재 5분씩 순차 처리하며 모든 구간의 시작 시간은 원본 PCM의 샘플 위치에서 계산합니다. 첫 유음 구간의 감지 언어를 이후 구간에 사용합니다. 편집 경계에 걸친 단어와 도중에 언어가 바뀌는 녹음에는 검토가 필요합니다. 1시간당 약 115 MB의 임시 PCM과 한 구간 약 10 MB의 WAV 저장 공간을 사용합니다. 파일과 모델은 자식 프로세스의 인자로 전달합니다.

TranscriptionBackend의 whisper.cpp 구현은 패키지 안의 whisper-cli를 호출합니다. Metal 자동 선택을 먼저 시도하고 실행 실패 시 CPU로 재시도합니다. CLI가 자체 CPU 폴백을 수행할 수도 있어 화면은 실제 계산 장치를 추정하지 않습니다. 구간의 출력은 정수 밀리초로 읽어 해당 청크 길이에 맞게 제한합니다. 완료 상태, 원문, 편집본, 원본 파일 식별 정보는 한 트랜잭션으로 기록합니다.

SQLite의 jobs는 녹음 경로와 실행 설정, segments는 (작업 UUID, 구간 순번)과 인식 원문 및 수정본, sources는 파일 식별 정보, prefs는 설정을 담습니다. 원본과 다른 파일이 동일 위치에 놓이면 재생을 보류합니다. 사용자가 지정한 Markdown 파일은 같은 디렉터리의 임시 파일에 먼저 쓴 뒤 교체합니다.
